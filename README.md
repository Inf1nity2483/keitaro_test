# Обёртка над Keitaro

Приложение создаёт кампании в Keitaro и редактирует офферы в их потоках. Черновик редактора хранится в Postgres. В трекер изменения попадают только после кнопки Push.

Стек: FastAPI, SQLAlchemy, Alembic, PostgreSQL, Docker Compose.

## Настройка

Нужен Docker.

Скопируйте `.env.example` в `.env` и заполните:

```text
KEITARO_API_KEY=ключ_из_профиля
CAMPAIGN_PREFIX=test_ivanov_
```

Ключ создаётся в админке Keitaro: иконка пользователя, Профиль, API ключи. Он показывается один раз. Префикс должен иметь вид `test_фамилия_`: кампания с именем `campaign1` уйдёт в трекер как `test_ivanov_campaign1`.

Группа и источник берутся из трекера по имени `FORTESTS`. Домен выбирается из API. Если доменов несколько и нужен конкретный, укажите его id в `KEITARO_DOMAIN_ID`.

Файл `.env` в репозиторий не коммитится.

## Запуск

Из корня проекта:

```powershell
docker compose up --build
```

Приложение: http://127.0.0.1:8000

Compose поднимает два сервиса: `app` и Postgres 16 (`db`). У базы пользователь `keitaro`, пароль `keitaro`, имя базы `keitaro`. Данные хранятся в томе `pgdata`.

Остановка:

```powershell
docker compose down
```

Том с данными при этом сохраняется. `docker compose down -v` удаляет его вместе с локальными черновиками.

Запросы в Keitaro идут через `curl`. Образ ставит его сам: клиенты на Python часто получают 403 от Cloudflare перед трекером.

## Миграции

Миграции лежат в `alembic/versions`. При старте контейнера выполняется:

```text
alembic upgrade head
```

Отдельно запускать её не нужно.

Для запуска без Docker нужны Python 3.11+, `curl` и Postgres с адресом из `DATABASE_URL`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
```

Проверка логики без трекера: `pytest`.

## Что делает создаватор

Форма принимает имя, гео через запятую (`MX,AU,RO`) и оффер из поиска. В Keitaro создаётся кампания:

- ротация потоков по позиции;
- домен, группа `FORTESTS`, источник `FORTESTS`;
- затраты CPC, стоимость 0 USD, стоимость из параметра `cost`;
- Flow 1 ловит переданные страны и отправляет их на `https://google.com`;
- Flow 2 забирает всех остальных и отправляет на выбранный оффер со долей 100%.

Идентификатор кампании генерируется приложением: пустой alias Keitaro не принимает.

## Что делает редактор

Кампанию можно открыть из списка или подтянуть по id кнопкой Fetch streams.

Поток без офферов показывается строкой. Куда он редиректит и какие у него фильтры, редактор не разбирает. Меняются только потоки, в которых есть офферы.

Доли активных офферов всегда целые и в сумме дают 100%. Лишний процент получает оффер с меньшим id. Три оффера делятся как 34/33/33, четыре как 25/25/25/25. Запиненная доля не пересчитывается, остаток делится между остальными. Если пины уже занимают 100% или после удаления запиненных процентов не на что разложить, действие отклоняется.

Жёлтый поток означает черновик: в Postgres правки уже есть, в Keitaro ещё нет. Обновление страницы черновик не стирает.

- Push отправляет в Keitaro активные офферы и их доли.
- Cancel откатывает черновик к последнему синхронизированному состоянию. Офферы, добавленные до публикации, из потока удаляются.
- Remove не стирает строку. Доля становится 0%, строка серая. После Push оффера в Keitaro нет, в редакторе он остаётся.
- Bring back возвращает серый оффер в расчёт и снова делает поток черновиком.
- Fetch streams забирает потоки из Keitaro. Оффер, которого в трекере больше нет, становится серым. Пока пользователь не нажмёт Bring back, такой поток не считается черновиком.
